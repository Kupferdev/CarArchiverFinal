# v35 Native SQLite / Electron ABI stabilization

## Changes
- `scripts/native-abi.mjs`: real Electron-runtime check of `better-sqlite3` (opens and queries in-memory SQLite DB).
- `postinstall`: ensures the installed native module matches the *installed* Electron version. Rebuilds with `@electron/rebuild` only when necessary.
- `predev`: checks/repairs native ABI before launching Vite/Electron.
- `native:check`: verifies Electron-native load without mutation.
- `native:rebuild`: force rebuild against the installed Electron version.
- Existing `test:db`, `test:car-owner` and `test:trash` Node-to-Electron fallback remains intact. No database schema changes.

## Windows verification requested
1. Back up user data; test using a separate development copy.
2. `npm ci` (should run postinstall automatically, unless scripts disabled).
3. `npm run native:check`
4. `npm run verify`
5. `npm run dev`
6. If ABI issue remains, run `npm run native:rebuild` and repeat check/dev.

## Limits / pending
- No node_modules in delivered source; Electron rebuild, TypeScript, ESLint, and SQLite integration tests **not executed** in this environment.
- `@typescript-eslint` v7 warns about TypeScript 5.9.3; not changed in this patch to avoid untested dependency upgrades.
- Legacy `electron-rebuild` package remains locked but is no longer used by the new script; remove in a separately verified dependency-refresh cycle.
- Electron-builder production packaging still requires a packaged-Windows smoke test.

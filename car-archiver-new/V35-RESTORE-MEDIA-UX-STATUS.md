# v35 data restore + media UX development preview

## Included in this source candidate
- Gallery now uses existing `BulkSelectionActions` (selection, bulk delete and exit selection). "Select all" / "Clear selection" is a supplementary action in selection mode. Photo opening still works in read-only service profiles.
- Photo thumbnails use the standard click pointer, not a magnifier. Lightbox toolbar now has one zoom readout and a grouped zoom-out/reset/zoom-in layout; X is separated. Arrows and keyboard navigation remain.
- Data and Storage settings divided into distinct spaced sections to prevent backup button from touching the CSV heading.
- Restore from an existing v35-format backup folder. The selected backup is checked for manifest, image-folder links, required tables and SQLite quick_check, then a pending request is stored; after user confirmation the app restarts. BEFORE reopening the database, the backup SQLite and media directory are staged and swapped, preserving the old database and media in a uniquely named `CarArchiver-before-restore-*` directory. A failed swap attempts to restore the previous files. No live SQLite overwrite.
- IPC for restore is added to preload whitelist and types.

## NOT completed / restrictions
- **Full customer, car, service and photo Trash with independent item recovery is still unimplemented.** Deletions from galleries currently take effect immediately. Do not test deletion using irreplaceable user data.
- The restore flow has NOT been exercised on a real Windows/Electron process with SQLite native binding. Validate with a throwaway data folder and a throwaway backup before trusting production backups. Save a separate offline copy of the active SQLite and media folder first.
- A pending restore that fails verification at startup intentionally stops the app rather than opening an inconsistent data set. Fix the backup/restore issue or remove the `pending-restore.json` marker in Electron userData only after preserving all original files.
- Restore is designed for backups generated by v35 (`CarArchiverBackup`, formatVersion 1, with ServiceMedia table). It is not a legacy archive migrator.
- UI confirmations in native Electron dialogs currently only include TR/EN wording; all app-level explanatory text is localized in 14 languages. Remaining native dialog localization is pending.
- Existing Service Media original files are stored outside SQLite. No physical media garbage collector or recovery management is included in this candidate.
- No MSIX/store work was performed per user request.
